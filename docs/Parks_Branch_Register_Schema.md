## 2. Build chain (rule 19.7)
`python3 pbr_build.py` runs stage (pbr_stage.py, rules in pbr_rules_v1.json, creditor histories in pbr_histories_v4.json) -> openpyxl write-only -> convert-route recalc (OOXMLRecalcMode=0) -> calamine verify -> ship. Scratch is wiped at start; nothing ships without a clean verify. Chain ~35 s at v4 and v5 (Creditor_Lines carries 20,718 history rows at v5). Needs `libreoffice-calc` and `poppler-utils` installed, not just `libreoffice-core`; a missing Calc component fails the convert route with "source file could not be loaded" on any file. Launch detached with `(setsid nohup python3 -u pbr_build.py > build.log 2>&1 < /dev/null &)`; a plain `nohup ... &` is killed when the tool call returns.

## 11. Journal_Pull, the pull list (rule 21, added v5)
- One row per TechOne **document file**, because that is the unit a Document Line Table export is pulled by and a file can carry many references: document 1252466 carries eight (IJ075145 to IJ075155). 56 document files cover all 3,287 journal lines and tie to their net exactly (Controls group 8: documents listed, lines covered, net in scope).
- Tiers: **A** no attachment in TechOne, so the Document Line Table is the evidence route (8 documents, $790,704.10 absolute net); **B** an attachment exists, sight it, a pull adds nothing (38); **C** RJ reversing journals, net exactly zero, read as a pair under rules 5 and 6 (6); **D** already embedded in PS_WP v127 Journal_Sources, where a re-pull is audited leg by leg and never re-captured, rule 12 (4). Ranked within tier by ABSOLUTE net movement into branch O110-O115, never gross, because gross double-counts both legs of a transfer.
- The tier screen reads v127 Journal_Sources by document file; that is what puts document 1247907 (GJ080271, $537,525.23 accrual reversal that does not pair in FY2026/27) into Tier D rather than the pull queue. The answer is already embedded in the PS & WP register.
- **Pull value** is the evidence judgement laid over the rule 21 ranking, because absolute net alone puts internal-charge allocations at the top: document 1252466 is $461,678.10 of rates, fire levy, water and garbage charges, but all 2,020 legs are already on the register with property-level narration, so a pull adds only the Council-side counterparty legs. High means a question the register cannot answer: a recode set that does not net inside O110-O115 (B-012), an accrual reversal that does not pair inside FY2026/27 (B-011), or a blank journal narration. 14 documents across Tiers A and B read High; only one of them is Tier A.
- `toolkit/branch/pbr_journal_pull_report.py` writes `reports/Journal_Pull_<ver>.md` and `.xlsx` from the shipped sheet without recomputing anything, so the report cannot disagree with the register. Refresh it after every journal batch (pipeline).
